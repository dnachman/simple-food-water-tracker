Food & Fluid Tracker
App map

Eight daily metrics, fast manual logging, adjustable goals, and a date-based history. The app runs in the browser; Sites hosts its static files.

Follow one tap

The four-fluid-ounce shortcut crosses the input, saving, and display boundaries without opening a form.

  1. Tap +4 fl ozapp.mjsThe quick-water handler creates a dated entry. saveChange reads the latest saved document.
  2. Save successfullystorage.mjscommitDocument validates and writes the document to localStorage before the displayed saved state changes.
  3. See the new totalui.mjsrenderDashboard sums the selected day and redraws the cards and entry list.

Sites serves the code. Intake records stay in this browser and origin; they are not sent to an application database.

Three-stop reference route

A reference for future navigation, not a claim that an interactive code tour was completed.

  1. Input and orchestration

    sites/food-fluid-tracker/dist/app.mjs

    Search for quick-water and saveChange. The selected date supplies the new entry's date; a failed write leaves the previous saved state unchanged.

  2. The persistence boundary

    sites/food-fluid-tracker/dist/storage.mjs

    Search for loadDocument and commitDocument. A missing key starts empty; invalid saved data produces an error and is preserved. Only successful writes reach the UI as saved changes.

  3. Visible progress

    Search for renderDashboard and metricCard. These use totalsForDate and goalProgress from domain.mjs, pairing bars with numbers and text status.

To change this, start here

Metric labels, units, totals, or goal comparisons

domain.mjs: METRICS, totalsForDate, and goalProgress. The form and card rendering consume these definitions. A unit change also requires deciding how existing saved values will be treated.

Dark palette, card spacing, or mobile full-screen forms

styles.css: :root, .metric, and the max-width:600px rules. Keep text and symbols alongside color, and preserve visible keyboard focus.

Food/fluid fields or entry corrections

ui.mjs: buildEntryFields, buildGoalFields, and restoreEntryFocus. Event handling lives in app.mjs; editEntry and removeEntry in domain.mjs preserve stable entry identity.

History and day rollover

app.mjs: selectDate, refresh, and scheduleMidnight. localDay, shiftDay, and dateAfterRollover in domain.mjs keep local calendar dates separate from UTC timestamps.

Sites publishing

.openai/hosting.json identifies the Site and its dist directory. The installed Sites helper synchronizes source, verifies the commit, packages the static files, and hands the matching artifact to private deployment. See spec.md → Sites Publication. No credentials belong in source.

A practice to reuse

Choose the smallest storage boundary that meets the product requirement, and verify that boundary separately from hosting. Here, same-browser saving allowed a static app with no database. storage.test.mjs checks reopening and failure-safe writes; the local browser check confirmed saved progress after reload.

A successful deployment proves publication, not browser persistence. Localhost and the Sites URL have separate storage. Test save → reload → history at the final origin whenever you change a hosting target. The agent's hosted check reached the private sign-in gate; it did not establish authenticated hosted persistence.
